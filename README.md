# tesla-screen-mirror

PCの画面を Tesla(Model Y L・日本仕様で想定)の車載ブラウザに映す試作Webアプリです。
**停車中に使うことを前提としています。走行中は使わないでください。**

- PCのブラウザで **送信ページ** を開き、画面共有を開始する
- Teslaのブラウザで **視聴ページ** を開き、接続コード(4桁)を入力する
- 映像は WebSocket 経由でサーバーが中継します(JPEG連番)

> 現在の段階: **WebSocket中継モードのみ**。WebRTCモード(同一LANで低遅延)は次の段階で追加予定です。

## かんたん起動(PC側)

インストール作業は自動で行われます。**最初にファイルをダブルクリックするだけ**です。

### 1. このプログラムをPCにダウンロードする

1. GitHub のこのリポジトリのページで、ブランチを `claude/websocket-relay-mode` に切り替える
2. 緑色の **Code** ボタン → **Download ZIP** を押す
3. ダウンロードしたZIPを右クリックして「すべて展開」(Macはダブルクリック)で、好きな場所に展開する

### 2. ダブルクリックで起動する

| PC | ダブルクリックするファイル |
| --- | --- |
| Windows | `start-windows.bat` |
| Mac | `start-mac.command` |

黒い画面(ターミナル)が開き、次のことを自動で行います。

1. **Node.js** が入っていなければインストールする
   - Windows: 途中で「変更を加えることを許可しますか?」と出たら「はい」。終わったら **もう一度ダブルクリック** してください
   - Mac: Homebrew がなければ Node.js のダウンロードページが開きます。「LTS」と書かれた方をインストールしてから、もう一度ダブルクリックしてください
2. 必要な部品をダウンロードする(`npm install`。初回のみ)
3. **cloudflared**(インターネットに公開するための道具)をこのフォルダの `.bin` にダウンロードする(初回のみ・約40MB)
4. サーバーを起動し、Tesla で開くURLを表示する
5. **送信ページがブラウザで自動的に開く**

#### 起動できないとき

- **Windows で「WindowsによってPCが保護されました」と出た**: 「詳細情報」→「実行」を押す
- **Mac で「開発元を検証できない」と出た**: いったん閉じて、「システム設定」→「プライバシーとセキュリティ」の下の方にある「このまま開く」を押す(古いmacOSでは、ファイルを右クリック →「開く」)

### 3. PCで画面共有を始める

自動で開いた送信ページ(`http://localhost:3000/send`)で、

1. 「開くURL」と「接続コード(4桁)」が表示されていることを確認する
2. 「画面共有を開始」を押し、映したい画面(画面全体またはウィンドウ)を選ぶ

ブラウザは **Chrome または Edge を推奨** します。
共有中は、黒い画面(ターミナル)と送信ページのタブを閉じないでください。別のタブや別のウィンドウに切り替えても送信が続くようにしていますが、
もし視聴側のfpsが極端に落ちる場合は、送信ページのウィンドウを最小化せずに残しておいてください。

終了するときは、黒い画面(ターミナル)を閉じます。公開URLは **起動するたびに変わります**。

### (参考)コマンドで起動する場合

ターミナルに慣れている場合は、Node.js 18 以上を入れたうえで次のコマンドでも同じことができます。

```sh
npm install
npm run tunnel
```

cloudflared がすでにインストールされていればそれを使い、なければ自動でダウンロードします。

## Tesla側での開き方

1. **停車して** パーキング(P)に入れる
2. 画面下のアプリランチャーから **ブラウザ** を開く
3. アドレスバーに、ターミナルや送信ページに表示された `https://…trycloudflare.com` を入力する
   - トップページがそのまま視聴ページです(`/send` などは付けません)
4. 画面のテンキーで **接続コード(4桁)** を入力する。4桁そろうと自動で接続します
5. 映像が表示されます。右上の小さな表示が **遅延(ms)とfps** です

### 視聴中の操作

画面をタップすると下部にボタンが出ます(6秒で自動的に隠れます)。

| ボタン | 動作 |
| --- | --- |
| 全画面 | ブラウザの全画面表示を試みます(Teslaのブラウザでは効かない場合があります) |
| 統計 非表示 / 表示 | 右上の遅延・fps表示を切り替えます |
| 切断 | 接続をやめて、コード入力画面に戻ります |

### もっと大きく表示したいとき

Teslaのブラウザはアドレスバーなどが常に表示されるため、映像の上下に余白が出ることがあります。
次の形式のURLを開くと、ブラウザの枠を減らした表示になる、という方法がオーナーの間で知られています(ソフトウェアのバージョンによっては使えません。動作は保証できません)。

```
https://www.youtube.com/redirect?q=https://xxxx-xxxx-xxxx-xxxx.trycloudflare.com
```

## Teslaを「2枚目のモニター(画面拡張)」として使う

ブラウザの機能だけでは新しい画面を作れないため、PC側に **仮想ディスプレイ** を追加してから、その画面を共有します。

1. 仮想ディスプレイを追加する
   - **Mac**: [BetterDisplay](https://github.com/waydabber/BetterDisplay) をインストールし、メニューバーのアイコンから「Create New Virtual Screen」で仮想スクリーンを作る(16:9 の 1920×1080 などがおすすめ)
   - **Windows**: [Virtual Display Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver) などの仮想ディスプレイドライバを入れる
   - ソフトを入れたくない場合は、HDMIの「ダミープラグ」(千円前後)をPCに挿すと、モニターがつながっているものとして扱われます
2. PCのディスプレイ設定で「拡張」になっていることを確認する(ミラーリングではなく)
3. 送信ページで「画面共有を開始」を押し、追加された方の画面を選ぶ

あとは、ウィンドウをその画面へドラッグすると Tesla に映ります。
マウスは仮想ディスプレイへ移動できますが、Teslaの画面をタッチしてPCを操作することはできません。

## 画質の調整

送信ページで、共有中でもその場で変えられます。設定はブラウザに保存されます。

| 項目 | 初期値 | 範囲 |
| --- | --- | --- |
| 最大解像度 | 1280 × 720 | 640 × 360 〜 1920 × 1080 |
| フレームレート | 20 fps | 5 〜 30 fps |
| JPEG画質 | 60% | 30 〜 95% |

- 画面の縦横比は維持され、指定より大きくはなりません(小さくなることはあります)
- 必要な通信量の目安は送信ページの「帯域」に表示されます。1280 × 720・20fps で、画面の内容によって **数Mbps〜15Mbps程度** です。
  車のモバイル回線やスマートフォンのテザリングで使う場合は、解像度・画質・fpsを下げると安定します
- 画面に動きがないときは、自動的に送信量を減らします(Chrome / Edge のみ)
- 回線が詰まったときは、古いフレームを捨てて最新の画面を優先します。遅延が大きいときは設定を下げてください

## 同じWi-Fi内で使う場合(トンネルなし)

PCとTeslaが同じWi-Fiにつながっている場合は、トンネルなしでも使えます。

```sh
npm start
```

Teslaのブラウザで `http://<PCのIPアドレス>:3000/` を開きます。PCのファイアウォールでポート3000の受信を許可する必要があります。

## 接続が切れたとき

- PC・Tesla のどちらも、通信が切れると自動で再接続します(最大5秒間隔)
- サーバーを再起動しても、送信ページを開いたままなら同じ接続コードで再開します
  - ただし `npm run tunnel` を再起動すると公開URLが変わるため、Tesla側で新しいURLを開き直す必要があります
- 送信ページを閉じてから10分たつと、その接続コードは無効になります

## セキュリティについて

試作のため、最低限の対策にとどめています。

- 接続コードを知らない人は映像を見られません
- コードの入力を **5分間に10回** 間違えると、その接続元からの入力をしばらく受け付けません(総当たり対策)
- 公開URLそのものもランダムで、起動のたびに変わります
- 送信は、サーバーを動かしているPC(localhost)からしかできません
- 1つの接続コードで同時に視聴できるのは3台までです
- コードを長くしたい場合は `CODE_LENGTH=6 npm run tunnel` のように起動します(4〜8桁)
- quick tunnel は Cloudflare を経由します。機密性の高い画面の共有は避けてください

## 設定(環境変数)

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PORT` | `3000` | サーバーのポート |
| `CODE_LENGTH` | `4` | 接続コードの桁数(4〜8) |
| `ALLOW_REMOTE_SENDER` | なし | `1` にすると、localhost 以外からの送信を許可します |
| `CLOUDFLARED` | `cloudflared` | cloudflared の実行ファイルのパス |
| `DEBUG_TUNNEL` | なし | `1` にすると cloudflared のログをそのまま表示します |
| `NO_OPEN` | なし | `1` にすると、起動時に送信ページを自動で開きません |

Windows の PowerShell では `$env:CODE_LENGTH=6; npm run tunnel` のように指定します。

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 「cloudflared の自動ダウンロードに失敗しました」 | インターネット接続を確認してもう一度起動する。それでもだめなら表示された手順で手動インストールする |
| 「cloudflared が終了しました」 | ネットワークの制限(社内ネットワークなど)で Cloudflare に接続できない可能性があります。`DEBUG_TUNNEL=1` で詳細を確認してください |
| 送信ページに「送信できません」 | `http://localhost:3000/send` をサーバーと同じPCで開いてください |
| 画面共有のボタンを押しても何も起きない | Chrome / Edge で、`http://localhost` から開いているか確認してください |
| 「映像を待っています…」のまま | 送信ページで画面共有を開始しているか確認してください |
| 遅延が大きい・カクつく | 送信ページで解像度・画質・fpsを下げてください |

## 構成

```
server.js           HTTPサーバー + WebSocket(ルーム管理・フレーム中継・時刻同期)
scripts/tunnel.js   サーバー起動 + cloudflared の自動ダウンロード・quick tunnel の起動とURL表示
start-windows.bat   Windows用のダブルクリック起動ファイル
start-mac.command   Mac用のダブルクリック起動ファイル
public/
  viewer.html/.js   視聴ページ(Tesla用、/ で配信)
  sender.html/.js   送信ページ(PC用、/send で配信)
  common.js         自動再接続WebSocket・時刻同期・フレーム形式
```

### 仕組み(WebSocket中継モード)

1. 送信ページが `getDisplayMedia` で画面をキャプチャし、指定のfpsでcanvasに縮小して JPEG にする
2. JPEG の先頭に16バイトのヘッダ(フレーム番号・撮影時刻)を付けて WebSocket でサーバーに送る
3. サーバーは同じ接続コードの視聴者にそのまま転送する(最新の1枚を保持し、途中から接続した視聴者にもすぐ表示)
4. 視聴ページはデコードして canvas に描画し、描画完了(ack)を送信側に返す
5. 送信側は ack が返ってこないフレームが一定数(約0.4秒分)を超えたら送信を控え、遅延がたまらないようにする

遅延は、送信側・視聴側の両方がサーバーと時刻を合わせ、「撮影した時刻」と「描画し終えた時刻」の差として表示しています。
